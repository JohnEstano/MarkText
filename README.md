# MarkText

**Watermarking and Detection of LLM-Generated Text**

A Python desktop application that generates text using a pretrained Qwen2.5 language model, optionally embedding an invisible statistical watermark via the Kirchenbauer et al. (2023) green/red list algorithm. A separate detector can later verify whether MarkText's watermark is present.

> **Limitation:** MarkText detects only text it generated with its own watermark key. It is **not** a universal AI-text detector.

---

## Description

MarkText runs entirely locally on a student laptop after a one-time model download. It uses Hugging Face's `WatermarkingConfig` (green/red list logit processor) during generation, and `WatermarkDetector` (statistical Z-score test) during detection. The process mirrors how Google's SynthID and related academic systems work.

## Features

- **Prompt-based generation** with Qwen2.5-Instruct
- **Normal generation** — plain Qwen output
- **Watermarked generation** — green/red list logit bias via HF `WatermarkingConfig`
- **Copy to clipboard** and **save as .txt**
- **Watermark detection** using HF `WatermarkDetector` and Z-score
- **Detection history** stored as CSV
- Completely offline after first model download
- No cloud API, no fine-tuning, no GPU required

## Technology

| Component | What |
|-----------|------|
| Language model | `Qwen/Qwen2.5-0.5B-Instruct` (Hugging Face Hub, ~500 MB) |
| Watermarking | Kirchenbauer et al. 2023 green/red list, via `transformers.WatermarkingConfig` |
| Detection | `transformers.WatermarkDetector` — Z-score statistical test |
| GUI | Python Tkinter + ttk |
| Framework | PyTorch + Hugging Face Transformers |

## Watermark Algorithm

The Kirchenbauer et al. (2023) algorithm partitions the vocabulary into a green list and a red list at each generation step, based on a deterministic hash of the recent token context and a secret key.

During **watermarked generation**, the logits of green-list tokens are boosted by a constant bias (default `3.0`), making them statistically more likely to be selected. Normal generation does not apply this bias.

During **detection**, the detector recomputes the green/red assignment for each token position and counts how many observed tokens fall in the green list. The Z-score measures how far the observed green fraction deviates from the expected fraction (default 50%).

A Z-score ≥ 4.0 is classified as **LIKELY MARKTEXT-GENERATED**. A Z-score between 2.0 and 4.0 is **POSSIBLE WATERMARK**. Below 2.0 is **NO WATERMARK**.

## Files

| File | Type | Purpose |
|------|------|---------|
| `config/watermark_config.json` | JSON | Watermark parameters, model ID, generation settings |
| `generated/normal/*.txt` | TXT | Unwatermarked generated documents |
| `generated/watermarked/*.txt` | TXT | Watermarked generated documents |
| `logs/detection_history.csv` | CSV | Append-only detection history log |

## File Handling

The application demonstrates every required file-handling mode:

- **Read** — config JSON, generated TXT files, external TXT files
- **Write** — generated TXT documents, JSON config
- **Update** — append detection records to CSV history
- **Process** — tokenize input text, run model inference, compute Z-score
- **Serialize** — model weights cached in Hugging Face cache (safetensors + pickle)

## Installation

Requires **Python 3.11+** with pip.

```bash
# Install PyTorch (CPU-only wheel, ~250 MB download)
pip install torch --index-url https://download.pytorch.org/whl/cpu

# Install Transformers
pip install transformers
```

## Running

```bash
python main.py
```

On first run, Hugging Face will download Qwen2.5-0.5B-Instruct (~500 MB) into `~/.cache/huggingface/hub`. Subsequent launches use the cached model.

## GUI

Four tabs:

1. **Generate** — Enter a prompt, choose Normal or Watermarked mode, set max tokens, click Generate. Results can be copied or saved.
2. **Detect** — Open a TXT file or paste text, click Analyze. Shows tokens analyzed, green fraction, Z-score, and classification.
3. **History** — Browse or clear detection history (CSV-backed).
4. **About** — Project description and limitations.

## Limitations

- Only detects text generated by MarkText with the correct watermark key.
- Requires enough analyzable text (200+ tokens recommended).
- Editing, paraphrasing, or heavily rewriting text can weaken or destroy the watermark.
- The underlying Qwen2.5 model generates text from its own training data; MarkText does not claim ownership of this model.
- CPU generation is slow (~1–4 tokens/sec); GPU is faster but not required.
